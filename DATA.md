# Data Availability & Reproducing

Model weights and generated datasets are **not tracked in git** (too large,
regenerable, or non-redistributable). They are intact on the author's machine —
a fresh clone just won't include them:

```
SecGPT/
├── SecGPTv2/
│   ├── data/
│   │   ├── cadre_kb.jsonl              ← 1.75 GB, local only (proprietary CADRE KB corpus)
│   │   ├── dfir_nexus_sources/         ← 23 JSONL, local only (DFIR-Nexus exports)
│   │   ├── KDD+.txt                    ← 20 MB, local only (NSL-KDD — public, re-downloadable)
│   │   ├── sms+spam+collection.zip     ← local only (UCI SMS Spam — public)
│   │   └── malimg.zip                  ← local only (Malimg — public; auto-extracted by build_corpus.py)
│   └── stage*/**/*.pt                  ← v2 checkpoints (~71 MB each), local only — retrain per llm_build.md
├── SecGPTv3/
│   └── stage*/**/model.safetensors     ← GPT-2 checkpoints (498 MB each), local only — retrain per doc.md
└── SecGPT-Prod/
    ├── data/sft_32k.jsonl              ← 31,111 pairs, regenerated by src/build_sft_32k.py
    └── stage1_sft/output/qwen_qlora/checkpoint-500/
        └── adapter_model.safetensors   ← 57 MB, THE trained LoRA, local only — retrain below (~2 h)
```

Public sources (NSL-KDD, UCI SMS, Malimg) restore the classification portions on
any machine. The proprietary CADRE KB and DFIR-Nexus exports are required for
full-size dataset regeneration — obtain your own copies.

## Full Prod reproduction (given the data above)

```bash
cd SecGPT-Prod
python src/build_sft_32k.py        # 1. dataset (~2 min)  → data/sft_32k.jsonl
python src/qlora_sft.py            # 2. QLoRA training (~2 h) → stage1_sft/output/qwen_qlora/
python src/quality_check.py        # 3. benchmark 14 prompts
```
